给 DeepSeek Harness 写一个邮件看板插件
2026/10/7

我在 DeepSeek Harness（下称 DSH）里同时挂着三个邮箱账号，每次想知道有没有漏掉邮件，都得开口让 agent 去查一遍。于是写了个插件：dsh-email-board —— 把各账号的未读邮件汇总成卡片列表，挂在 DSH 右侧栏的自定义 tab 里。

它长什么样

  • 右侧栏「开始」页里多出一个邮件看板入口，点开就是卡片列表；
  • 按账号分组，每张卡片是发件人、主题、时间，带附件的邮件和已标星的邮件各有一个小标记；
  • 顶部是未读总数和「刷新」按钮，账号 chip 可以只看某一个账号；
  • 只读：不会标记已读、不会删除、不会发信。想看正文仍然用会话里的 email_read。

装与用

它依赖 dsh-email（看板读它的账号设置，不自己存凭据）。在 DSH 的「插件」页填仓库目录的绝对路径安装，等价于：

cd $env:DSH_PROFILE_DIR
pnpm add link:<dsh-email-board 绝对路径>
# 再把 "dsh-email-board" 追加到 package.json 的 dsh.profile.bundles

重启 DSH，打开右侧栏 → 开始页 → 邮件看板。取数是手动的：打开时拉一次，之后只有点「刷新」才会重新读邮箱。

三个技术坑（写给同样想写 DSH 插件的人）

一、pnpm 的 file: 依赖是快照，不是活链接。 用 pnpm add file:<目录> 装插件，pnpm 会把文件拷贝进 node_modules；之后你在源码目录里怎么改，宿主读的都是那份冻结副本——重启多少次都没用。要在源码目录里边改边跑，用 link:<绝对路径>（或手工建 junction），让 profile 读活文件。

二、改代码一定要重启 DSH。 宿主进程里的插件模块 import 一次就进了缓存；改 profile 配置（bundle 列表、patch 层）只会重载配置树，不会让宿主重新 import 模块。桌面版的 base 组合包以 hmr.root: [] 启动，等于关掉了模块文件监听，所以也没有热重载可指望。配置重载唯一能救的是「新装的插件」——全新模块，缓存里没有它。

三、受限环境里 git 推送可能卡在 TLS 阶段。 git 默认走 Windows schannel，在某些受限令牌下会报 SEC_E_NO_CREDENTIALS；换成 OpenSSL 后端就能过：

git -c http.sslBackend=openssl push -u origin main

另外凭据助手需要创建命名管道，权限更紧的环境下会被拒——那一次操作得放宽权限，或者干脆在有代理的终端里自己推。

实现三两句话

插件分两半。宿主半侧不复制 dsh-email 的任何内部实现，只读它的设置行，再用它公开导出的 resolveEmailSettings / toEmailConfig / EmailPool 取每个账号的未读信封——也就是 email_list 的那套实现，只是不经过模型；结果挂到一条同源只读路由上。客户端半侧注册右侧栏的 tab 类型与正文槽位（sidebar.right.pane.tab），拿到 JSON 渲染卡片。

那条只读路由带同源判定：Sec-Fetch-Site 不是 same-origin/none 一律 403，非 GET 一律 405。未读邮件的标题和发件人是隐私，不该被任意网页一次 GET 读走。

路由还有一个 20 秒的短路缓存和「同一时刻只跑一轮 IMAP」的单飞，连点刷新也不会把邮箱服务器打爆。

番外：鲸鱼真可爱

写这个插件的时候，DSH 界面右下角一直蹲着这只鲸鱼，时不时冒一句「哦鲸鲸……」。它跟邮件看板没什么关系，但既然这篇是流水账，就顺手放上来：
